## A. "Attention Is All You Need": the concepts

**A1. Why attention**
- Recurrence is sequential (no parallelism over time) and long-range information must survive many steps; attention connects any two positions in one step
- Cost: self-attention is O(T²·C) per layer vs. O(T·C²) for recurrence; shorter path lengths between tokens
- Motivation for the causal variant: language modelling predicts token t+1 from tokens ≤ t
- *Figure:* `report/architecture.png` (attention detail panel)
- *Code:* [`CausalSelfAttention`](../src/model.py#L128)

**A2. Scaled dot-product attention**
- Q, K, V as learned linear maps of the same input; scores = QKᵀ/√d_k; softmax over keys; weighted sum of V
- Why the 1/√d_k: dot product of two unit-variance vectors has variance d_k, so large d_k pushes softmax into saturation (tiny gradients); *you should be able to show the variance argument*
- Softmax rows sum to 1, so each output is a convex combination of value vectors
- *Figure:* `report/figures/causal_mask.png` (unmasked vs masked softmax)
- *Code:* scores [`model.py:173`](../src/model.py#L173), softmax [`:177`](../src/model.py#L177), weighted sum [`:179`](../src/model.py#L179)
- *Test:* `tests/test_blocks.py::test_attention_matches_naive_per_head_loop` (vectorised == explicit loops)

**A3. Multi-head attention**
- n_head parallel attentions on C/n_head-dimensional subspaces, concatenated, then W_O; different heads can specialise (see Experiment 9)
- Same parameter count as single-head with full width; heads are a reshape, not extra weights
- *Figure:* Experiment 9 heatmaps, `results/exp9_attention_overview.png` **T4** (small-model version of the same script runs on the CPU demo model)
- *Code:* split into heads [`model.py:163`](../src/model.py#L163), merge [`:180`](../src/model.py#L180), output projection [`:181`](../src/model.py#L181)

**A4. Position information**
- Attention is permutation-equivariant: without positions, "dog bites man" = "man bites dog" (bag of tokens)
- Sinusoidal encoding: PE(pos,2i)=sin(pos/10000^(2i/C)), PE(pos,2i+1)=cos(...); fixed, no parameters, relative offsets are linear maps of each other
- *Figure:* `report/figures/positional_encoding.png`
- *Code:* [`sinusoidal_encoding`](../src/model.py#L39), applied in [`Embeddings.forward`](../src/model.py#L88)

**A5. Feed-forward network, residuals, LayerNorm**
- Position-wise FFN: expand 4×, nonlinearity, project back; ~2/3 of the parameters (Phase 3 table: 65.8% MLP vs 32.9% attention)
- Residual connections keep a gradient highway; LayerNorm normalises per token over features (not over the batch)
- *Table:* parameter breakdown, `python -m src.model --config configs/small.yaml`
- *Code:* [`LayerNorm`](../src/model.py#L106) (verified against `nn.LayerNorm` in `tests/test_blocks.py`), [`MLP`](../src/model.py#L186), [`Block`](../src/model.py#L202)

**A6. Encoder–decoder structure of the original model**
- Encoder: unmasked self-attention. Decoder: masked self-attention + cross-attention to the encoder output
- *(see B2 for the comparison table)*

## B. From the Transformer to GPT-2: what changed

**B1. Architectural differences (table)**

| aspect | Vaswani et al. | GPT-2 | in this repo |
|---|---|---|---|
| stack | encoder + decoder | decoder only | decoder only |
| cross-attention | yes (decoder → encoder) | none | none |
| positions | fixed sinusoidal | learned table | both, `model.pos_encoding` |
| LayerNorm placement | after the residual add (post-norm) | before each sub-layer (pre-norm) + final LN | both, `model.norm_position` |
| activation | ReLU | GELU (tanh approx.) | GELU (tanh) |
| embedding / softmax weights | shared | tied input/output embedding | tied, `model.tie_weights` |
| init | Glorot-style | N(0, 0.02); residual projections ÷ √(2·n_layer) | GPT-2 init |
| tokenizer | word-piece BPE | byte-level BPE | char-level, char-BPE, byte-BPE (mine) |

- *Code:* config flags [`GPTConfig`](../src/model.py#L22); pre/post-norm [`Block.forward`](../src/model.py#L219); init [`GPT.__init__`](../src/model.py#L235) (scaling at [`:260`](../src/model.py#L260))
- *Deviations to mention:* sinusoidal mode multiplies token embeddings by √C (Vaswani does; GPT-2 does not); no final LayerNorm in post-norm mode

**B2. Masked vs. unmasked vs. cross-attention**

| | mask | queries from | keys/values from | used in |
|---|---|---|---|---|
| unmasked self-attention | none | same sequence | same sequence | encoder (BERT-style) |
| masked (causal) self-attention | lower-triangular | same sequence | same sequence | decoder, GPT |
| cross-attention | none | decoder states | encoder output | encoder–decoder (translation) |

- GPT only needs the middle row; training exploits it: one forward pass gives T next-token predictions
- Causality test: changing a future token must not change earlier logits (`tests/test_gpt.py::test_model_is_causal`)
- *Figure:* `report/figures/causal_mask.png`
- *Code:* mask buffer [`model.py:149`](../src/model.py#L149), applied [`:176`](../src/model.py#L176)

**B3. Positional encodings: learned vs sinusoidal**
- Both inject order; sinusoidal needs no parameters and could extrapolate in principle, learned is limited to block_size
- Absolute positions limit the KV cache once the window slides (see D, limitations)
- *Experiment 6:* `results/exp6_pos_encoding.md` **T4**

**B4. Norm placement**
- Post-norm: the residual stream itself is normalised; pre-norm keeps an un-normalised identity path
- *Experiment 5:* val loss, gradient norms, loss spikes, divergence at higher LR, `results/exp5_norm.md` **T4**

**D2. Limitations (bullets to expand)**
- Small models and short training; single seed per configuration (no error bars): differences < ~0.02 nats are not trustworthy
- Absolute position embeddings: KV-cache speed-up exists only while prompt + output ≤ block_size
- Character-level default vocabulary: long sequences, no word-level knowledge; BPE here is a simplified pre-tokenizer (stdlib `re`, `\w`)
- Head labels in Experiment 9 are threshold heuristics; sinusoidal-vs-learned and norm comparisons use a short schedule
- Normalised-vs-raw Amharic loss is not like-for-like (different text)
- Demo checkpoints are CPU-trained and rough

**D3. Lessons learned (real events from the build)**
- YAML 1.1 parses `1e-3` as a string → silent config bug; fixed and tested
- A naive BPE trainer re-counting all pairs took 3 min for English and would take far longer for Ge'ez → incremental counts (identical merges, tested against the naive version): 182 s → 10 s
- A resume test only passes if the LR schedule is identical: added `stop_iter`
- Test data mistakes caught by tests that were otherwise right (e.g. ዓ folds to ኣ, not አ)
- Byte-level BPE's cost for non-Latin scripts shows up as fragment tokens
- In-process UI tests hid a real bug: `streamlit run app/app.py` puts `app/` on the import path, so `import app` found the script instead of the package; only a test in a fresh process reproduced it (`tests/test_app.py::test_app_runs_in_a_fresh_process_like_streamlit_does`)
- Comparing English and Amharic needs the right unit: bits/char, bits/byte and bits/word tell different stories (see `results/amharic/FINDINGS.md` §6)

## E. Amharic (Ge'ez) tokenization study

**E1. Why Ge'ez is different**
- Abugida/syllabary: hundreds of consonant+vowel characters (351 distinct vs 65 in the English corpus), 3 bytes per character in UTF-8
- Ethiopic punctuation (። ፣ ፤ ፡) is kept; homophone letters (ሀ/ሐ/ኀ, ሰ/ሠ, አ/ዐ, ጸ/ፀ) are spelled inconsistently
- *Table:* `results/amharic/tokenizer_analysis.md` → "Corpus facts"
- *Code:* [`data/amharic/prepare.py`](../data/amharic/prepare.py), [`data/amharic/normalize.py`](../data/amharic/normalize.py)

**E2. Three tokenizers, two languages**
- Char-level, char-BPE, byte-BPE at vocab 500 / 1000 / 4000: fertility (tokens/word), tokens/char, bytes/token, types to cover 95% / 99%
- Sequence inflation of byte-level vs char-level; fragment tokens (half characters) and how fast they vanish with vocab size
- *Figures:* `results/amharic/fertility_vs_vocab.png`, `tokens_per_word.png`, `byte_inflation.png`; byte-BPE fragment figure from `exp10_amharic.py`
- *Tables:* `results/amharic/tokenizer_stats.csv`, `exp10_amharic.md`

**E3. Learned merges**
- Early merges: byte-BPE re-assembles characters first; char-BPE discovers syllable pairs, then whole words and affixes
